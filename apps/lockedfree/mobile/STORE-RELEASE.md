# Rulebook store release
The mobile app (identifier com.askakshay.lockedfree on both platforms) bundles an offline whole-share sizing calculator and a local notebook. The market brief, Calls, Stocks and Practice links open the hosted product online. Clearing the notebook removes its records. No sign-in, real-money trades, paid subscription, or delivery SDK is bundled. Web newsletter registration is free. Existing browser data does not migrate to the notebook.

## Build / verify
From apps/lockedfree/mobile run npm ci and npx cap sync. For iOS open ios/App/App.xcodeproj (Swift Package Manager); select App, your team, and a real device or simulator. Android: open android/ in Android Studio, install SDK 36, use JDK 21, run ./gradlew :app:bundleRelease in android/. The lockedfree-mobile Actions workflow produces an unsigned release bundle, not a store submission. Never commit signing keys, provisioning profiles or passwords.

## Owner checklist
1. Apple: [enroll](https://developer.apple.com/programs/enroll/) under the intended legal publisher, complete verification and accept agreements. In [Certificates, Identifiers & Profiles](https://developer.apple.com/account/resources/identifiers/list) register the identifier; create the corresponding Rulebook record in [App Store Connect](https://appstoreconnect.apple.com/). Check display-name and identifier availability before signing. Set the team in Xcode, archive for a generic iOS device, validate and upload using Organizer. Test through TestFlight before submitting. Simulator builds cannot be uploaded.
2. Android: create and verify the appropriate personal or organization [Play Console account](https://play.google.com/console/signup). Create the app, configure Play App Signing and keep the upload key private. Generate a signed Android App Bundle with Android Studio, upload it first to internal testing, then complete any closed-testing and production-access requirements shown for the account. Check the current target API policy before release. Every subsequent upload needs a higher versionCode/build number.
3. On actual devices try airplane mode, whole-share sizing, closing and reopening the notebook, deletion, system back navigation, screen-reader labels and external market links. Capture current app screenshots (not browser mockups). Use a real support contact, https://lockedfree.askakshay.com/about/#contact and https://lockedfree.askakshay.com/privacy/.
4. Complete age/content ratings, privacy and data-safety questionnaires, export compliance, and the Google financial-features declaration based on the actual release. Distinguish local practice records from requests made after opening the hosted site. Review price-data redistribution terms before enabling native market-data distribution. Confirm Apple and Google publisher and financial-services requirements for your distribution countries; educational status is not an exemption.
5. Suggested listing: “Practise sizing a stock position on paper. Set a budget and loss limit, save the entry and stop to a private notebook, and revisit it offline. Explore the public simulated portfolio online.” Review notes: “No login or payment. Enter budget 10,000, loss limit 200, entry 100, stop 95. The app sizes 40 shares. Save, relaunch offline and inspect the notebook.” Reviewers decide eligibility, including Apple's [minimum functionality rules](https://developer.apple.com/app-store/review/guidelines/#minimum-functionality). Review [Play testing requirements](https://support.google.com/googleplay/android-developer/answer/14151465) for the specific account.

## Newsletter activation (separate from app-store billing)
Register a Brevo sender and verify your sending domain; create a dedicated list and a double-opt-in template with the provider's confirmation link. Set BREVO_API_KEY as a Cloudflare Worker secret, and BREVO_LIST_ID and BREVO_DOI_TEMPLATE_ID as secrets or durable deployment configuration on the lockedfree Worker (not in Git). Use the production hostname. With no credentials, the site only records interest. When enabled, only new explicit provider opt-ins request confirmation; the old list is not exported. Send campaigns from the confirmed list with an unsubscribe link. Test once using your own address, verify confirmation, unsubscribe and suppression before announcing delivery. For deletion requests, remove the local record and separately handle the contact/suppression record in Brevo. No campaign or newsletter schedule is enabled by this release.
