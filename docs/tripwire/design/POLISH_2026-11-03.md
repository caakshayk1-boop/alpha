# Tripwire experience update — 3 November 2026

The live-site audit found crowded mobile company names, repeated market explanations, an unbalanced desktop Markets page, chart controls below their plots, and a first-use flow that presented two equivalent exit buttons.

This update covers five areas:

1. **Layout:** a compact company-search action for new users; one market takeaway; expandable validation diagnostics; full company names in mobile Discover rows; action buttons separated from identity and price; balanced indices/breadth columns, a full-width sector section and a commodity strip.
2. **Charts:** controls before the main chart in DOM/tab order, larger touch plots, relative-performance gap in the scrubber tooltip, separate index sparklines and daily-range indicators, sector tiles available as an alternate disclosure instead of a second expanded sector view. Chart maths, price adjustment, benchmark windows and table alternatives are unchanged.
3. **Visual system:** shared `polish.css` after the foundation, using the existing tokens; tighter section spacing, larger key figures, raised briefing and empty-state surfaces, readable company identities, consistent controls.
4. **Motion:** new users start with motion enabled; existing saved preferences remain intact, including legacy motion migration. Device reduced motion disables movement. Sheets, presses, tabs and confirmations provide brief feedback. Scrolling does not transform content; chart lines do not repeatedly draw themselves.
5. **Onboarding and copy:** one Explore markets action plus real example company links; shorter first-use explanation; one primary My Desk action with an optional research guide; visible quick research presets; advanced column/condition controls under Research tools; expanded observation methodology available on demand. Signal percentiles are explicitly labelled.

No engine, ledger, trading rule, persistence schema or API contract changes. Data freshness and evidence limitations remain visible. No external tracking or new dependency is introduced.

Verification uses the existing type, unit, token, budget, data, browser, accessibility, chart and motion checks. Browser journey selectors are updated for the intentional navigation and disclosure changes. Local browser checks use installed Google Chrome via a temporary Playwright launch override because downloading the pinned Chromium stalled; that override is not shipped.
