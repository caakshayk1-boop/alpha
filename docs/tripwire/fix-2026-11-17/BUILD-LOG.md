## Site audit (TRIPWIRE_REVIEW.md, 18 Nov 2026): what was checked, built and left
**Checked first (each claim against the live site or the repo).** Confirmed: `/data/screen.json` (862,444 B) and `/data/signals.json` are served with no `Content-Encoding`; fonts are `no-cache`; unknown paths and `/privacy/`, `/favicon.ico` return 200 with the app shell; the manifest says `#07090D` against the page's `#0A0A0B`; the boot logo dot is periwinkle `#A5B4FF`; `cache.addAll` over the whole shell in the service worker; none of the four shipped fonts contains the rupee sign U+20B9 (checked with fontTools on the woff2 files: Inter, Fraunces, JetBrains Mono latin and latin-ext all False), so the rupee is always drawn by a system font.
**Root cause found, different from the audit's fix.** The global `Cache-Control: no-cache, no-transform` is deliberate (it stops Cloudflare injecting an analytics beacon the CSP blocks; see `shellAsset` in `worker.js`), and `no-transform` is also what stops the edge compressing JSON. The page is gzipped inside the Worker; `/app.*` has its own header and is already served as br. Fix: `/data/*` gets `Cache-Control: no-cache` (no `no-transform`), the same mechanism that already compresses the scripts. JSON carries no beacon, so the CSP reason does not apply. **Measured live after deploy (version `29295817-5964-4861-94d4-96f96a70be72`, 18 Nov 2026): `/data/screen.json` now answers `content-encoding: br`, 172,808 bytes on the wire against 862,444; `/data/signals.json` is br too.**
**Built.**
- Headers: `/data/*` compressible; `/fonts/*` `public, max-age=31536000, immutable` (font files are never edited in place; a changed font would need a new file name).
- Real 404s: `not_found_handling` is now `404-page` (the shell ships as `404.html`, so a bad path shows the app with status 404); `/privacy/` and `/terms/` are meta-refresh stubs to `#/privacy` and `#/terms` (noindex); `/favicon.ico` is a real 32 px file.
