## 3. News: a focused brief, not headline aggregation
Today shows the best 5 distinct events, "Show 5 more" up to 10. Never pad: if three qualify, show three and say quietly there are no more verified updates. Full archive and controls on a dedicated News page.
Each row: short factual headline; source and publication age; one event-type tag; affected company/sector/market; optional one-line factual summary; source link. Multi-source coverage and reasoning in an expandable drawer. A summary must be grounded in retrieved permitted content; with only a headline do not invent what the article says or infer sentiment.
Tabs: All / Market / Following / Paper book. Following with no names gets a useful empty state and a Discover link. Do not silently seed Following from experimental auto-book holdings. Any personalisation must be visible and user-controllable.
No generic stock quote pages, routine technical-price commentary, unrelated international news or syndicated copies as separate important events. Fallback expansion must never bypass entity matching or quality eligibility. An old event keeps its original date and gets no "New" badge merely because it was fetched again.
Scheduling and delivery: a server-side scheduler independent of an open browser; every 15 minutes during NSE sessions, 30 outside, by the exchange calendar (holidays, special sessions). Authorised sources within rate limits; free sources may be delayed or unavailable; no promise of exchange-grade real time. One shared snapshot per scope rather than a fetch per visitor; ETag/conditional requests where supported, deduplicated fetches, bounded exponential backoff with jitter, timeouts, per-source circuit breakers, atomic snapshot publication. The frontend checks a light version endpoint while visible, pauses when hidden, revalidates on focus, respects Retry-After, rate-limits "Refresh now" and shows Checking / No new qualifying stories / Updated / Temporarily unavailable. Preserve reading position; offer "3 new updates" instead of reordering under the reader; no animated ticker tapes.
Record scheduledAt, startedAt, completedAt, lastSuccessfulAt, nextScheduledAt, publication timestamps, source status, snapshot version, rejection counts. Partial-source failure keeps the good sources and labels coverage partial. Total failure keeps the last good snapshot: "News delayed - last successful check [time zone]". Never call cached content live.
Pipeline: normalise permitted feed items -> validate URL/date/entity -> reject noise -> cluster events -> rank -> diversify -> publish an immutable snapshot. Model: itemId, canonicalUrl, sourceId, sourceTitle, headline, publishedAt, fetchedAt, updatedAt, sourceTimezone, entities with confidence, eventType, eventClusterId, summary plus provenance, qualityFlags, relevanceScore, rankingVersion. UTC internally, explicit IST in the UI. Missing publication time is unknown, not "just now". Reject or quarantine impossible future timestamps.
Entity matching uses names, exchanges, aliases and symbol disambiguation; no substring matching for common words/tickers; generic company landing pages are not event articles; distinguish a dated exchange filing from an announcements index page.
Ranking: documented deterministic ranker (event significance, verified entity relevance, source reliability, recency decay, novelty, user relevance). An LLM is optional, not required. Do not label a keyword classifier as AI analysis. Do not rank by attention-grabbing language or bullishness. Cluster syndicated reports into one event (primary source plus "2 more sources"); keep materially different developments; diversity caps (no more than two events from one company in the default five; a documented override for a major event); market-wide stories stay represented when credible, without filler quotas. Prefer company/exchange filings for company events, primary announcements for policy/macro. Do not scrape restricted article bodies or bypass access controls. Attribute and link original sources; store only permitted content.

## 4. Discover: one screener, two renderers
Reproduction to fix first: Uptrend -> 39 -> Table -> RSI 30-56 -> 12 -> sort by symbol -> search PETRONET -> 1 -> open PETRONET -> browser Back. Observed: default List, 988 names, empty search, cleared filters.
One canonical DiscoverState: query, conditions, sector, size class, trend, view, sort column/direction, visible columns, page/cursor, comparison selection, scroll anchor. Both renderers consume the same evaluated dataset. Filter/sort/query/view URL-backed; private journal/financial inputs never in URLs. replaceState for rapid edits, history entries for meaningful navigation, stable serialisation. Back, Forward, refresh and shared links reproduce the screen. Preserve scroll/selected company on return.
Above both renderers: the same search, filter button with count, active chips, clear-all, result count, sort selector and view switch. Table column filters are shortcuts into the same condition model; funnel hit targets comfortably tappable, keyboard accessible, visible active status, named labels such as "Filter RSI".
Filter controls for validated data: sector, size, trend, price, liquidity, RSI, distance to high, PE, revenue growth, relative performance, applicable fundamentals. Do not offer a financial-sector metric the eligibility layer excludes. Distinguish missing/unknown from zero; let users include unknowns explicitly. Validate min/max, units, negatives, nonsensical ranges. Explain unavailable filters inline.
Table: Follow, Compare, company links, sortable headers with aria-sort, sticky header, pinned company identity, visible horizontal scroll, sensible column presets. Match list sort exactly (stable ties, null handling). Compare selections survive view changes. Filters apply to the full eligible dataset, not the rendered 40 rows. Virtualisation must keep keyboard focus.
Keep live quote displays separate from end-of-day screening predicates; both renderers identify the calculation basis; a live update must not silently change a last-close eligibility decision. If live filtering is offered it is labelled and every selected field supports it.

## 6. Quality of interaction, appropriate to the platform
No SwiftUI skill may exist: inspect installed project skills/AGENTS.md and use relevant Apple HIG/accessibility/motion skills if present, naming exactly which; else official Apple guidance. Do not claim to have used an absent skill; do not convert the web app to SwiftUI. References: https://developer.apple.com/design/human-interface-guidelines/motion , https://developer.apple.com/documentation/swiftui/animations . For the web app use state-driven transitions in the existing stack (CSS/Web Animations). Keep business logic independent of UI.
Visual direction: restrained premium research app, charcoal surfaces, crisp hierarchy, one electric-lime action accent and semantic gain/loss colours. Keep proportional body text; refine size, contrast, line length, spacing; mono/tabular only for numbers. Avoid stacked borders, repetitive glass panels, low-contrast microcopy, arbitrary gradients, decorative currency animation.
Motion tokens (proposals): press 100-140 ms; chip/segmented selection 160-220 ms; disclosure 180-240 ms; sheet/navigation 220-300 ms. Interruptible, context-preserving, honours prefers-reduced-motion and the in-app setting. No chart redraw on each quote tick, no animated P&L celebration, no scroll hijacking, no endless shimmer after failure. Shared selection indicators; chart entry animation only on first reveal; news arrivals via a quiet update badge. Sheets trap focus, restore it, close on Escape, avoid keyboard/safe-area overlap. Visible pressed, hover, focus, disabled, loading, error, success states. Capability detection is not proof that vibration works. Reduced motion keeps useful non-motion feedback. 44px touch areas for primary mobile controls; verify contrast, 200% zoom, screen-reader names, keyboard order; no overlap at 360/390/430/768/1024/1440 and on a real iPhone/PWA.
