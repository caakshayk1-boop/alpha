# Tripwire visual and followed-company update

The followed-company feed now groups changes into one company card. Only the latest event for each topic remains: a later crossing above the 200-day average supersedes an earlier crossing below it. Independent topics and separate thesis invalidations remain available. Results reminders use today's countdown, disappear when past or rescheduled, and preserve dismissal when the data day changes. An older cached screen cannot replace a newer comparison baseline. Saved notes and backup formats are unchanged.

Markets has a sector treemap with 1D, 1W and 1M windows. Selecting a sector opens its companies, leaders and laggards, plus a table alternative. Area represents last-session traded value, not market capitalisation; small cells have a disclosed minimum size. Missing or stale observations are excluded. Return colours reflect the actual sign, including negative sector leaders.

Company charts have a gradient area and high/low close annotations; homepage charts have more vertical space. Target ladders measure rendered labels and assign separate rows when necessary, including narrow screens and wider fonts. Motion follows the existing user and reduced-motion settings.

Market conditions now read “Market supportive” or “Market cautious.” Market checks, the independent paper engines, and statistical validation are explained separately on Signals. A passing market filter is not presented as proof that a strategy works.

The initial JavaScript closure is approximately 85 KB gzip. Dashboard and macro routes load on navigation; the welcome screen no longer waits for a separate route chunk or eagerly downloads every other screen. The unused initial font preload is removed. HTML compression preserves the existing CSP and no-transform response policy and honours clients that do not accept gzip.

Validation includes regression tests for contradictory events, current countdowns, rescheduling, stale caches, dismissal and heat-map calculations; browser checks cover grouped cards, undo, narrow layouts and target-label overlap. A local Lighthouse 13.6 mobile run in an earlier session measured performance 99, LCP 1.7 s, FCP 0.7 s, CLS 0 and TBT 110 ms. That figure was not re-measured when this was written, and a lab run is not a production PageSpeed guarantee: re-measure on the deployed site.

News retains the on-demand fallback already shipped. A live check returned 30 articles when the scheduled snapshot was late. The separate cron-to-GitHub nudge still requires the owner's GITHUB_DISPATCH_TOKEN; this update does not claim that GitHub's scheduler is reliable or re-date old articles.

## Added in the same release

- **Followed companies on My Desk** show the close and the day's move, then only the facts worth a glance (`followfacts.ts`): an approaching results date, a move of 3% or more, the position against the 52-week range, an extreme RSI, and the trend, at most three, most useful first. A figure the screen does not carry says nothing. The last recorded change, if any, comes first.
- **The market-gate pill** keeps its accessible name beginning with its visible words ("Market cautious. New setups are paused: 2 of 4 market checks pass."), which the accessibility check requires (WCAG 2.5.3, label in name). It has one dot per market check, and the Signals page lists each check with its figures.
- **Other screens' code is prefetched when it is needed**, not at start-up: a returning visitor's page fetches it once loaded and idle, a first-time visitor's welcome screen fetches it on first touch (`prefetch.ts`, `tests/prefetch.mjs`). Removing the prefetch altogether made every tab switch wait on the network.
- **Heat map labels** are sized per cell from its own width and height, use a short code where the name will not fit at a readable size, and print nothing rather than a cut-off label (`cellLabel`, swept over cell sizes in `sectorheat.test.ts`).

## Known and not fixed

- A chart test (`charts.mjs`, "the chart card holds its place while loading") fails intermittently in about 1 run in 8 on the deployed build as well: the plot is present and correctly sized in every failing run, so it looks like a Playwright visibility-polling stall, not a user-visible fault. Not confirmed beyond that.
- Company stories still depend on GitHub's scheduler; see the news note above.
